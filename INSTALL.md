\# Инструкция по установке и запуску ShoeStore



\## 1. Назначение



Данная инструкция предназначена для установки и запуска приложения ShoeStore на компьютере под управлением Windows.



Приложение поставляется в виде готовой Windows-сборки. Для работы с данными необходимо отдельно запустить сервер базы данных PostgreSQL с помощью Docker Desktop.



\*\*Важно:\*\* база данных не включена в EXE-файл. Она запускается отдельно в контейнере Docker.



\## 2. Системные требования



Для установки и работы приложения необходимы:



\- Windows 10 или Windows 11;

\- установленный Docker Desktop;

\- запущенный Docker Desktop с поддержкой Docker Compose;

\- доступное свободное место для приложения, контейнеров и данных базы;

\- свободный порт 5433 на компьютере.



\## 3. Подготовка базы данных



\### 3.1. Установка Docker Desktop



Установите Docker Desktop и запустите его. Перед дальнейшими действиями убедитесь, что Docker Desktop полностью запущен.



\### 3.2. Настройка переменных окружения



Откройте папку `deployment`, расположенную в комплекте поставки.



Создайте рабочий файл `.env` на основе шаблона `.env.example`:



```powershell

Copy-Item .env.example .env

```



Откройте файл `.env` и укажите параметры подключения к PostgreSQL. Замените демонстрационный пароль на собственный.



Параметры в `.env` должны соответствовать настройкам базы данных, используемым приложением.



Не передавайте файл `.env` третьим лицам и не публикуйте его в репозитории.



\### 3.3. Запуск PostgreSQL



В PowerShell перейдите в папку `deployment`:



```powershell

cd путь\_к\_комплекту\\ShoeStore-release\\deployment

```



Запустите контейнеры:



```powershell

docker compose up -d

```



Проверьте состояние контейнеров:



```powershell

docker compose ps

```



Убедитесь, что сервис базы данных находится в состоянии `Up`.



\### 3.4. Первичная загрузка структуры базы данных



Если база данных создаётся впервые и ещё не содержит таблиц, выполните импорт SQL-файла `database/shoe\_store.sql`.



Например, если имя базы данных и пользователь заданы в `.env` как `shoes\_shop` и `postgres`, выполните:



```powershell

Get-Content .\\database\\shoe\_store.sql | docker compose exec -T db psql -U postgres -d shoes\_shop

```



Если в `.env` используются другие значения, замените имя пользователя и базы данных в команде на соответствующие значения.



Импорт выполняется только при первоначальной настройке пустой базы данных. Не выполняйте его повторно для уже используемой базы без необходимости: это может привести к ошибкам или изменению существующих данных.



\## 4. Настройка приложения



В корне комплекта поставки находится шаблон `config.ini.example`.



Создайте на его основе файл `config.ini`:



```powershell

Copy-Item .\\config.ini.example .\\application\\ShoeStore\\config.ini

```



Откройте созданный файл:



```powershell

notepad .\\application\\ShoeStore\\config.ini

```



Укажите параметры подключения к базе данных. Они должны соответствовать фактическим настройкам PostgreSQL.



Для подключения приложения с Windows к контейнеру необходимо использовать `localhost` и опубликованный Docker порт хоста.



Сохраните файл после изменения параметров.



\## 5. Запуск приложения



После запуска базы данных и настройки `config.ini` откройте папку:



`application\\ShoeStore`



Запустите файл:



`ShoeStore.exe`



Приложение готово к работе после успешного подключения к базе данных.



Папку `\_internal` необходимо сохранять рядом с исполняемым файлом. Она содержит компоненты, необходимые для запуска приложения.



\## 6. Остановка приложения и базы данных



Сначала закройте приложение ShoeStore.



Затем откройте PowerShell в папке `deployment` и выполните:



```powershell

docker compose down

```



Команда остановит и удалит контейнеры, но сохранит данные PostgreSQL в Docker volume.



\*\*Не используйте команду `docker compose down -v`, если требуется сохранить данные базы данных.\*\*



\## 7. Типичные проблемы



\*\*Приложение не подключается к базе данных.\*\*



Проверьте, запущен ли Docker Desktop, работает ли контейнер PostgreSQL и правильно ли указаны параметры в `config.ini`.



\*\*Контейнер базы данных не запускается.\*\*



Проверьте содержимое `.env`, доступность указанного порта и вывод команды:



```powershell

docker compose logs db

```



\*\*Не удаётся выполнить импорт SQL-файла.\*\*



Убедитесь, что база данных создана, контейнер запущен, а имя пользователя и базы данных в команде импорта соответствуют настройкам `.env`.



\*\*Приложение не запускается.\*\*



Проверьте наличие `ShoeStore.exe` и папки `\_internal`. Не перемещайте исполняемый файл отдельно от этой папки.



\## 8. Проверка подключения к базе данных



Для проверки состояния инфраструктуры выполните:



```powershell

docker compose ps

```



Для просмотра журнала PostgreSQL:



```powershell

docker compose logs db

```



При необходимости можно использовать диагностический сервис, предусмотренный в `compose.yaml`:



```powershell

docker compose run --rm db-check

```



Диагностическая проверка позволяет проверить доступность базы данных с использованием заданных параметров окружения.



\## 9. Состав комплекта поставки



В комплект поставки входят:



\- `application/ShoeStore` — готовая Windows-сборка приложения;

\- `deployment/compose.yaml` — конфигурация запуска Docker-контейнеров;

\- `deployment/.env.example` — шаблон переменных окружения;

\- `deployment/database/shoe\_store.sql` — SQL-файл базы данных;

\- `deployment/db-check` — файлы диагностического сервиса;

\- `config.ini.example` — шаблон конфигурации приложения;

\- `README.md` — описание проекта;

\- `INSTALL.md` — инструкция по установке и запуску.



Фактические параметры подключения и пароли задаются пользователем при установке и не включаются в комплект поставки.
